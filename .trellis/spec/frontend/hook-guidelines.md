## 基础约束

1. **零假设**：不确定是否使用 hook 或类似机制时先询问。
2. **复用优先**：未来已有自定义 hook 或工具函数时，优先复用。
3. **最小实现**：只抽取确实复用或隔离复杂逻辑所需的 hook。
4. **手术式修改**：不为了统一风格重写无关 hook。
5. **简单命名**：hook 或等价抽象命名应直观、容易搜索。

---

## 数据与副作用

- 服务端数据请求和缓存应优先交给 TanStack Query。
- 自定义 hook 只在复用逻辑或隔离复杂副作用时创建，不为了形式抽象。
- 不要用自定义 hook 绕开统一 API client、认证或错误处理契约。
- 接入真实源码后，应补充自定义 hook 位置、命名、返回值约定、数据请求方式和实际示例路径。
