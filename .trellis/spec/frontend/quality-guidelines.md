## 代码质量

### 基础原则

1. **先思考，零假设**：需求不清、能力不明、实现路径有分歧时停止并询问。
2. **最小可用**：只写完成当前任务所需的最少代码，不添加未请求功能。
3. **复用优先**：已有组件、hook、工具、样式或状态模式可用时优先复用。
4. **手术式修改**：严格限制改动范围，不重构无关页面或组件。
5. **简单命名**：变量、方法、组件、hook、文件名保持直观、容易搜索。
6. **清理自己的变更**：只删除本次改动造成的死代码或无用导入；既有问题只说明，不擅自处理。

### 禁止模式

- 不基于真实源码编造框架、目录、状态库、样式库或测试命令。
- 不为了兼容未知旧逻辑写臃肿代码。
- 不用临时 hack 掩盖根因。
- 不顺手格式化或优化无关文件。

## 常见问题

### typecheck 失败

1. 检查 TypeScript 配置：`tsconfig.app.json`
2. 检查类型定义是否完整
3. 检查导入路径是否正确

### build 失败

1. 先运行 typecheck 排除类型错误
2. 检查 Vite 配置
3. 检查依赖是否安装

### 样式不生效

1. 检查 Tailwind CSS v4 配置：`@import "tailwindcss"`
2. 检查类名是否正确
3. 检查 `@theme` 配置
