# 前端设计方案分析

## 调试环境

- 前端：`http://localhost:5173/`
- 后端：`http://localhost:3000/`
- 数据库：Docker Postgres `watermenu-postgres`
- 登录账号：`admin@example.com / change-me-now`
- 调试视口：移动端 375px 宽度
- 截图：
  - `../current-home-mobile.png`

## 当前真实页面观察

### 登录页

- 结构简洁，只有 emoji、标题、副标题、登录表单和注册提示。
- 当前 `slate-50` 背景 + 白卡 + slate 文本，功能清楚但品牌感弱。
- 登录页缺少与主应用共享的视觉元素，如纸张背景、厨房色彩、品牌装饰。

### 首页 / 推荐 tab

- 顶部标题、tab、推荐操作卡片、最近用餐卡片都采用基础后台样式。
- 推荐操作区信息密度低，适合加入更有仪式感的“今天菜单”视觉，但不能改变按钮流程。
- 最近用餐卡片需要和历史记录卡片保持一致，适合统一成“记录纸条”风格。

### 菜品管理 tab

- 菜品卡片有较多操作按钮：编辑、停用、图库、做法、记录已吃。
- 这里是最容易被过度设计影响可读性的区域；按钮必须保持清楚、可点击。
- 菜品标签、停用标签和封面占位适合统一成厨房标签/贴纸视觉。

### 历史记录 tab

- 筛选项多，信息密度最高。
- 需要保持表单控件高度一致、焦点明显、禁用态可辨认。
- 不适合重型装饰；更适合浅色纸张卡片、轻量边框和统一标签系统。

## 设计方向结论

采用“温暖厨房手账风”，但在信息密集页面保持克制。

### 视觉语言

- 背景：奶油米白 + 轻微纸张纹理/径向色斑。
- 主色：番茄红用于主行动与焦点。
- 辅色：橄榄绿用于正向标签/餐次/推荐理由。
- 中性色：酱油棕/墨棕用于正文和边框。
- 强调色：蛋黄/浅琥珀用于盲盒、highlight、贴纸。

### 字体

- 不新增外部字体。
- 用系统 serif 栈作为标题/品牌字体，制造菜谱手账感。
- 正文保留系统 sans 栈但移除硬编码 Inter。

### 组件策略

- `index.css` 定义主题颜色、字体栈、纸纹背景、通用动效、可访问 focus ring。
- `ui.tsx` 统一基础 UI：Button、SecondaryButton、Input、Select、Card、PageHeader、EmptyState、Spinner、ErrorBanner。
- 业务组件只做必要 className 协调，不改 hooks/API/业务状态。

### 动效策略

- 卡片 hover/active 轻微浮起或按压。
- 推荐结果/盲盒结果使用短距离 fade/slide in。
- 所有动画在 `prefers-reduced-motion: reduce` 下禁用或降级。

## 风险与约束

- 不能为了风格牺牲移动端操作密度，尤其菜品卡片 5 个按钮必须保持可点击。
- 不应引入复杂自定义组件抽象；现有规范要求 Tailwind 类直接写 JSX，不抽 class 常量。
- 不应使用在线字体、外部纹理图片或动画库。
- 后端本地调试时 Prisma schema 需要与数据库同步；这属于调试环境问题，不应纳入前端代码改动。

## 推荐实现切分

1. 全局主题：`frontend/src/index.css`
2. 基础 UI：`frontend/src/components/ui.tsx`
3. 页面骨架：`login-page.tsx`、`home-page.tsx`
4. 业务组件视觉协调：推荐、历史、最近记录、菜品表单、餐次标签等
5. 真实浏览器调试 + typecheck/build
